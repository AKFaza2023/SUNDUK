# SUNDUK 0.4.0-dev.1 — цикл 01, 18.11.2026

Общая модель записей вынесена в `Sunduk.Core` (net8.0, без WPF и SQLite).
`IItemRepository` описывает локальные операции над записями. Реализация в

адаптер `DatabaseService` и утверждённую компоновку главной страницы.

Репозиторий проверен перед работой: main `f65c5f5fd5098283cd4864208bd3ecd3252de708`.
Архив переноса содержал другие версии App.xaml, MainWindow.xaml и MainWindow.xaml.cs,

## Локальная модель

- Старый целочисленный `Items.Id` сохранён: это LocalId, а не сетевой ключ.
- `GlobalId` — UUID, создаваемый при добавлении и сохраняемый в базе.
- `WorkspaceId` — идентификатор пространства; текущая программа открывает
  только своё локальное личное пространство.
- `Revision` — целочисленная версия записи, начиная с 1.
- `UpdatedAt` и `DeletedAt` — время изменения и отметка мягкого удаления.
- Создание, изменение и удаление выполняются в явной транзакции.
- Изменение / удаление требует ожидаемую Revision; устаревшее изменение
  завершается ItemConflictException и не затирает более новые данные.
- Все запросы ограничены WorkspaceId. Это граница локальных данных,
  а не реализованная серверная авторизация.
- Поиск регистронезависим для русского текста. `%` и `_` — обычные символы.

Сетевой протокол, права команды, очередь синхронизации, история версий и
восстановление удалённых записей этим кодом ещё не реализованы. Update и Delete
подготовлены и проверены в хранилище; кнопок редактирования и удаления пока нет.

## Перенос существующей базы

Путь остаётся `%LOCALAPPDATA%\SUNDUK\Data\sunduk.db`.
Для исходной схемы 0.3 (`user_version=0`, шесть исходных колонок Items)
до миграции создаётся резервная копия через SQLite BackupDatabase в папке
`Data\Backups`. Это учитывает подтверждённые записи в WAL, если он используется.

В одной транзакции добавляются Workspaces, LocalState и новые колонки Items,
каждая запись получает постоянный UUID и локальное пространство. Исходные
Id, Kind, Title, Category, Note, CreatedAt сохраняются дословно. Сравнение
исходных колонок до и после переноса обнаруживает изменения от старых триггеров.
Индексы и триггеры старой таблицы сохраняются. Только успешный перенос
фиксирует `PRAGMA user_version=1`. Повторное открытие не меняет идентификаторы.

Неизвестная / более новая схема и некорректная исходная дата останавливают
обновление. При ошибке транзакция откатывается; приложение сообщает об ошибке
и закрывается, вместо работы с неподключённой базой. Новая база создаётся
пустой: демонстрационные записи больше не добавляются автоматически.

После обновления базы старую EXE 0.3 использовать с ней нельзя: старые INSERT
без идентификаторов отклоняются. Для отката закройте все экземпляры программы,
сохраните текущую базу и восстановите предмиграционную копию под именем
sunduk.db. Такая копия содержит состояние до переноса; более поздние изменения
в неё не входят. Не заменяйте работающий файл и его журналы вручную.

Резервная копия и финальная миграция — две последовательные операции. Если
старая программа продолжает запись между ними, новые подтверждённые строки
тоже попадут в миграцию, но могут отсутствовать в более ранней копии. Перед
обновлением нужно закрыть остальные экземпляры SUNDUK.

## Проверки

`dotnet build tests/Sunduk.StorageChecks -c Release -m:1 -p:TreatWarningsAsErrors=true`

`dotnet tests/Sunduk.StorageChecks/bin/Release/net8.0/Sunduk.StorageChecks.dll`

17 интеграционных сценариев используют настоящую SQLite во временных папках:
новая база, перенос, WAL-backup, откат, неизвестная схема, перезапуск,
конфликт версий, конкурирующие редакторы, пространства, мягкое удаление,
русский поиск, неизменность идентичности, валидация, сохранение старых объектов
схемы, конкурирующий запуск, изменяющий данные триггер, частичная схема.

Для Windows CI добавлен отдельный режим `--desktop-smoke <путь к EXE>`:
он проверяет появление окна, базу и нормальное закрытие с чистым профилем,
затем с базой 0.3. Если папка данных уже существует, режим отказывается её
трогать. Это технический тест для изолированного runner, не команда для
рабочего компьютера пользователя.
